# Evidence-matched direct-model comparison

The direct baseline and V2 selected identical actions and scopes across all 120
event rows, including candidate carry-forward rows. Both matched all 72 reviewed
action checkpoints on the 24-case authored repository challenge. This experiment
does not demonstrate an accuracy advantage from Bayesian updating.

## Results

| Observation | V2 cost + safety | Direct model |
| --- | ---: | ---: |
| Reviewed action checkpoints | 72/72 | 72/72 |
| Final SAFE on stipulated legitimate cases | 8/8 | 8/8 |
| Final FLAG on stipulated scam cases | 8/8 | 8/8 |
| Final HOLD on unknown cases | 8/8 | 8/8 |
| Final SAFE on scam / FLAG on legitimate | 0 / 0 | 0 / 0 |
| Known-label terminal decision cost | 0 | 0 |
| All-case terminal decision cost including unknown HOLDs | 4 | 4 |
| Model calls in the completed run | 56 | 96 |
| Candidate-triggered model calls | 0 | 0 |
| Whole-run elapsed time, ms | 105,107 | 277,073 |

Costs use the student-assumed relative matrix: SAFE on scam 2, FLAG on legitimate
1, HOLD 0.5 in either state. Unknown cases remain unknown: their eight HOLDs cost
4 regardless of which binary state applies. Costs charge only the terminal action;
they exclude inspection, accumulated delay, model bills and operational losses.

The baseline made a model decision on each recruiter/check event; V2 used model
request extraction and deterministic decisions when scripted checks arrived.
The direct baseline's median call-wrapper duration was 2,465 ms. These are single
sequential runs with different prompts, input sizes and call schedules. Neither
token usage nor billed dollars was captured, and elapsed time does not isolate
provider inference, SDK overhead or retries. Fewer calls are observed; a dollar
saving or general latency advantage is not established.

## Citation failures and protocol revisions

Two earlier partial runs are retained, each stopping after three model calls at
the first clean inspection:

- [Version 1 partial run](direct-baseline-2026-10-28T12-24-47-986Z.json): the
  original rejected quote was not retained. A separate
  [diagnostic](direct-baseline-e4-diagnostic-2026-10-28.json) showed the validator
  rejected the arrived structured outcome `no_harmful_behaviour_found` because
  only narrative findings/messages were allowed. This identifies a contract
  mismatch without proving that the original response contained that exact quote.
- [Version 2 partial run](direct-baseline-2026-10-28T12-33-07-348Z.json): outcome
  citations were allowed, but the response quoted
  `outcome: "no_harmful_behaviour_found"`, including the field label. Strict exact
  matching rejected it.
- Version 3 separates `event_id`, `field` and `quote`, keeping exact matching.
  It passed a separate [one-prefix smoke test](direct-baseline-e4-diagnostic-v3-2026-10-28.json)
  before the completed run. No action targets, numerical model or safety contract
  changed. Prior calls/probes are additional development usage, excluded from the
  completed-run call count of 96.

These are interface/format reliability failures, not demonstrated scam-policy
failures. The successful third protocol does not erase the failed attempts.
Its zero validation errors cannot estimate the original protocol's reliability.

## Interpretation and next experiment

Both systems received the same arrived evidence and assumed cost context using
the same configured model alias. Ground truth and reviewed targets were excluded
from model input. The direct model received no prior/likelihood table or separate
Bayesian updater. It did receive the same explicit safety contract, including
HOLD until inspection and assessment authorisation are resolved.

The baseline prompt was specified after V2 results were seen and revised after
baseline failures. This is a development comparison, not an independent holdout.
The 24 cases comprise eight matched triplets with shared prefixes; they are not
24 independent task families or a representative traffic/prevalence sample.
Repository findings and authorisation are scripted, not real inspection results.
No repository was fetched, installed or executed in this experiment.

Exact citations establish provenance within the supplied prefix. They do not
independently verify a finding or prove that every explanation is semantically
supported. No independent semantic adjudication or repeated-run reliability study
was performed. Precision/recall on these stipulated labels is not a deployment
accuracy estimate, and the V2 posterior is not calibrated by this comparison.

The useful next question is whether the systems remain safe when evidence is
missing, contradicted, duplicated or manipulated. Define and review those targets
before running a new robustness set; preserve a separate result for every failed
run. Live inspection accuracy, check costs/information selection and calibration
remain separate work. The student-written Week 2 paper and discussion update are
still outstanding; do not invent policy failures to satisfy a failure-count gate.

Validation after the baseline implementation: `npm run check:v2` passed formatting,
lint, strict TypeScript checks and all 129 local tests. Local tests require no
model credentials or live model API.
